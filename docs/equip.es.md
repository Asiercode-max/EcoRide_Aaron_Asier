# Equipo y reparto de tareas

El proyecto lo desarrolla una pareja de alumnos de 2n de DAM. Cada persona asume un rol principal, pero las decisiones técnicas se toman conjuntamente y todo el código pasa por revisión de la otra persona.

## Roles

| Rol | Responsabilidad | Entrega |
| --- | --- | --- |
| Backend y base de datos | API REST, modelo de datos, migraciones, seguridad | Código del servicio, colección de pruebas de la API |
| Aplicación y documentación | Pantallas Flutter, integración con la API, sitio MkDocs | APK de pruebas, documentación publicada |

## Reparto por fases

| Fase | Backend | Aplicación y documentación |
| --- | --- | --- |
| 1. Análisis | Modelo de datos y rutas de la API | Estructura del sitio y wireframes |
| 2. Desarrollo | Autenticación y estaciones | Registro, mapa y navegación |
| 3. Integración | Reservas e historial | Reserva y pantalla de trayecto |
| 4. Cierre | Pruebas de integración y despliegue | Capturas, memoria y entrega |

## Coordinación

- **Repositorio**: dos ramas de trabajo (`backend` y `app`) y *pull requests* hacia `main`.
- **Reuniones**: una revisión corta al final de cada sesión de clase para repartir el trabajo siguiente.
- **Documentación**: cualquier cambio de la API se actualiza esa misma semana en [API](api.es.md) y en [Arquitectura](arquitectura.es.md).

!!! note "Nombres en el documento de entrega"
    En esta página se describen los roles, no las personas. Los nombres y el reparto firmado por la pareja van en el documento breve de entrega, junto con las capturas y la dificultad encontrada.
