# Team and task split

The project is developed by a pair of second-year DAM students. Each person takes a primary role, but technical decisions are made together and all code goes through the other person's review.

## Roles

| Role | Responsibility | Deliverable |
| --- | --- | --- |
| Backend and database | REST API, data model, migrations, security | Service code, API test collection |
| App and documentation | Flutter screens, API integration, MkDocs site | Test APK, published documentation |

## Split by phase

| Phase | Backend | App and documentation |
| --- | --- | --- |
| 1. Analysis | Data model and API routes | Site structure and wireframes |
| 2. Development | Authentication and stations | Sign-up, map and navigation |
| 3. Integration | Reservations and history | Reservation and trip screen |
| 4. Wrap-up | Integration tests and deployment | Screenshots, report and submission |

## Coordination

- **Repository**: two working branches (`backend` and `app`) and *pull requests* into `main`.
- **Meetings**: a short review at the end of each class session to split the next task.
- **Documentation**: any API change is updated that same week in [API](api.en.md) and [Architecture](arquitectura.en.md).

!!! note "Names in the submission document"
    This page describes roles, not people. Names and the signed task split belong in the short submission document, together with the screenshots and the difficulty found.
